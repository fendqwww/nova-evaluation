# Деплой NOVA на Vercel

Пошагово. Всё, что можно было сделать в коде, уже сделано — ниже только то,
что требует вашего аккаунта.

---

## 1. База данных: Neon

Vercel не имеет диска: файловая система там только для чтения и живёт ровно
один запрос. Поэтому база — внешняя.

1. Зарегистрируйтесь на [neon.com](https://neon.com) (бесплатный тариф).
2. Create project → регион **AWS eu-central-1 (Frankfurt)** — ближайший к
   пользователям из России.
3. На экране проекта скопируйте **Connection string** вида:

   ```
   postgresql://neondb_owner:XXXX@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   Берите строку с **`-pooler`** в адресе — это пулер соединений. Без него
   несколько одновременных пользователей исчерпают лимит подключений.

---

## 2. Локальная проверка (5 минут, необязательно, но лучше сделать)

Подставьте строку в `.env.local`:

```
DATABASE_URL=postgresql://…?sslmode=require
```

Примените схему и проверьте живую базу:

```bash
npx prisma migrate deploy
npx tsx scripts/verify-database.ts
```

Второй скрипт создаёт временного пользователя, прогоняет гонки лимитов
(30 одновременных запросов против лимита 20 → должно пройти ровно 20) и
удаляет за собой. Если он говорит «База готова к работе» — можно деплоить.

## 3. Переменные окружения в Vercel

vercel.com → проект → Settings → Environment Variables. Все три окружения
(Production, Preview, Development).

| Переменная | Значение | Обязательна |
|---|---|---|
| `DATABASE_URL` | строка Neon с `-pooler` | да |
| `TELEGRAM_BOT_TOKEN` | токен `@NovaEvaluation_bot` | да |
| `TELEGRAM_SUPPORT_BOT_TOKEN` | токен `@evaluationsupport_bot` | для поддержки |
| `TELEGRAM_WEBHOOK_SECRET` | значение из `.env.local` | для поддержки |
| `SUPPORT_ADMIN_IDS` | `7346458421` | для поддержки |
| `CRON_SECRET` | Vercel подставит сам при включении Cron | для рассылки |
| `GEMINI_API_KEY` | ключ Google AI Studio | для AI |
| `ADMIN_SECRET` | значение из `.env.local` (≥16 символов) | для выдачи тарифов |

Без первых двух сборка падает на проверке переменных — это сделано намеренно,
чтобы не выкатить приложение, которое сломается на первом же пользователе.
Остальные необязательны: без `GEMINI_API_KEY` коуч отвечает собственными
расчётами, без токена поддержки кнопки просто открывают чат с ботом.

## 4. Деплой

1. [vercel.com/new](https://vercel.com/new) → Import Git Repository →
   `fendqwww/nova-evaluation`.
2. Framework Next.js определится сам, ничего менять не нужно.
3. Deploy.

Команда сборки — `prisma migrate deploy && next build`: миграции применяются
автоматически при каждом деплое, отдельный шаг не нужен.

Получите адрес вида `nova-evaluation.vercel.app`.

## 5. Привязка ботов к домену

**Основной бот** — @BotFather → `/mybots` → `@NovaEvaluation_bot`:

- `Bot Settings` → `Menu Button` → указать URL приложения;
- `Configure Mini App` → `Enable` → тот же URL.

Второе включает ссылку `?startapp` — именно её открывают все кнопки
«Начать бесплатно» на лендинге. Без этого они откроют чат с ботом, а не
приложение.

Затем откройте один раз в браузере — это зарегистрирует вебхук, меню команд и
кнопку Mini App одним запросом:

```
https://ВАШ-ДОМЕН/api/telegram/app/setup?secret=ЗНАЧЕНИЕ_ADMIN_SECRET
```

**Бот поддержки:**

1. Напишите `/start` боту `@evaluationsupport_bot` со своего аккаунта
   (`7346458421`). Telegram запрещает ботам писать первыми — без этого шага
   уведомления о новых обращениях до вас не дойдут.
2. Откройте один раз в браузере:

   ```
   https://ВАШ-ДОМЕН/api/telegram/support/setup?secret=ЗНАЧЕНИЕ_ADMIN_SECRET
   ```

   Это зарегистрирует webhook. Ответ `{"ok":true}` — готово.

## 6. Напоминания в основном боте

Планировщик рассчитан на запуск **раз в час**: «утро» у пользователей наступает
в разное время, и он сам решает, кому сейчас уместно написать. Но на тарифе
**Vercel Hobby расписание чаще одного раза в сутки не принимается** — деплой
падает с `invalid cron schedule`. Из-за этого расписание однажды убрали из
`vercel.json` целиком, и рассылка перестала запускаться чем-либо вообще.

Поэтому запусков теперь два, и они дополняют друг друга:

| Откуда | Как часто | Роль |
| --- | --- | --- |
| `vercel.json` | раз в сутки, 06:00 UTC | пол: что-то уйдёт в любом случае |
| `.github/workflows/notifications.yml` | раз в час | то, ради чего писался планировщик |

Vercel включит своё расписание сам при первом деплое и подставит `CRON_SECRET`.

**Чтобы заработал часовой запуск**, добавьте в GitHub два секрета репозитория
(Settings → Secrets and variables → Actions):

| Секрет | Значение |
| --- | --- |
| `NOVA_APP_URL` | `https://ВАШ-ДОМЕН` — без слэша на конце |
| `NOVA_ADMIN_SECRET` | то же, что `ADMIN_SECRET` на Vercel |

Проверить, не дожидаясь часа: вкладка Actions → *Nova notifications sweep* →
**Run workflow**. В логе будет сводка прохода.

Два запуска не дублируют сообщения: право на отправку занимается в базе до
самой отправки, поэтому второй заход в тот же час ничего не пошлёт повторно.

Если тариф Vercel поднимут до Pro — часовое расписание можно перенести прямо в
`vercel.json` и workflow отключить.

**Что получает пользователь.** Не больше двух сообщений в сутки:

- **утром (8:00–11:00 по его времени)** — сводка: сколько спал прошлой ночью,
  что стоит в расписании на сегодня, жива ли серия;
- **вечером (19:00–22:00)** — только если что-то осталось незакрытым:
  неотмеченные привычки, пустой дневник питания или просроченные задачи. День
  закрыт полностью — бот молчит.

**Ушедшим** (3+ дня без входа) вместо утреннего приходит возвратное — раз в
неделю, с тремя разными текстами в зависимости от того, сколько прошло. В
каждом есть кнопка «Больше не писать».

Уважаются переключатели в «Настройках» → «Уведомления»: выключенное питание
означает, что про питание бот не напомнит.

**Проверить рассылку вручную**, не дожидаясь часа:

```
https://ВАШ-ДОМЕН/api/cron/notifications?secret=ЗНАЧЕНИЕ_ADMIN_SECRET
```

Ответ покажет, скольких рассмотрели, скольким отправили и скольких пропустили.
Повторный вызов в тот же час никому ничего не отправит второй раз — защита от
дублей на уровне базы.

## 7. Как выдавать тарифы

Всё делается в боте поддержки, терминал не нужен.

**Кнопками.** Обращение в категории «💳 Оплата» приходит с кнопками
«💎 PLUS 30д» и «👑 MAX 30д» прямо под карточкой. Одно касание — тариф выдан,
пользователю ушло уведомление. На тикетах других категорий этих кнопок нет,
чтобы не выдать тариф не тому.

**Командой** — когда нужен другой срок или человек написал не через тикет:

```
/plan @user            посмотреть текущий тариф
/plan @user plus       PLUS на 30 дней
/plan @user max 90     MAX на 90 дней
/plan @user plus 0     бессрочно
/plan @user free       снять тариф
```

Вместо `@user` можно указать числовой Telegram ID. Полный список — `/admin`.

Продление работает накопительно: выдать PLUS человеку, у которого осталось
12 дней, — значит дать ему 12 + 30. Повышение PLUS → MAX начинает новый период,
а не наследует дни дешёвого тарифа.

Если пользователь ни разу не открывал бота поддержки, Telegram не даст
отправить ему уведомление. Тариф всё равно выдаётся, а в ответе админу будет
сказано, что сообщение не дошло — тогда скажите ему сами.

## 8. Панель со статистикой

Открывается **внутри приложения**: Профиль → «Панель». Строка видна только тем,
чей числовой Telegram-id перечислен в `SUPPORT_ADMIN_IDS` — тот же список, что
пускает к командам бота поддержки. Отдельной переменной нет намеренно: два
списка одних и тех же людей однажды разойдутся.

Что показывает: сколько людей всего, сколько дошли до конца знакомства, сколько
бросили на нём, сколько заходили за сутки / неделю / месяц, разбивка по тарифам,
расход AI за текущий месяц, что и в каком объёме люди ведут (тренировки,
питание, сон, привычки, задачи, цели, уход), состояние бота и поддержки.

Пароля нет и не нужно. Внутри Mini App личность приходит подписанной Telegram и
проверяется на каждом запросе (`features/admin/server/admin-guard.ts`) — это
более сильная проверка, чем общий секрет, который можно переслать в сообщении.
Спрятанная строка меню при этом ограничением доступа не считается: сервер
отвечает отказом любому, кого нет в списке, даже если он знает адрес.

Панель только читает. Единственное действие, меняющее данные, — выдача тарифа,
и она осталась там же, где была: раздел 7 и кнопки в боте поддержки.

Персональных данных в ответе нет: ни имён, ни telegramId, ни чьих-либо записей —
только агрегаты по всей базе.

## 9. Проверка после запуска

- [ ] Лендинг открывается, «Начать бесплатно» ведёт в `@NovaEvaluation_bot`
- [ ] Приложение открывается внутри Telegram, проходит онбординг
- [ ] Первый экран — согласия, без отметок дальше не пускает
- [ ] Обращение в `@evaluationsupport_bot` создаёт тикет и приходит вам
- [ ] Обращение в категории «Оплата» приходит с кнопками выдачи тарифа
- [ ] `/plan @свой_username plus` выдаёт тариф, в приложении меняются лимиты
- [ ] Приложение открывается в Telegram Web на компьютере
- [ ] `@NovaEvaluation_bot` отвечает на `/start`, в меню видны пять команд
- [ ] `/today` показывает сводку, `/stop` отключает напоминания
- [ ] Ручной вызов `/api/cron/notifications` отвечает статистикой без ошибок
- [ ] `/legal/privacy`, `/legal/offer`, `/legal/consent`,
      `/legal/recommendations` открываются
- [ ] В профиле видна строка «Панель», открывается и показывает числа
- [ ] У обычного пользователя строки «Панель» в профиле нет
- [ ] `/dev/ui-check` на проде отдаёт 404

## Что осталось незакрытым

**Реквизиты оператора.** `src/shared/config/legal.ts` пуст: без наименования,
ИНН и адреса оферта и согласие юридической силы не имеют. Приложение честно
помечает документы как черновик, но для публичного запуска это надо заполнить.

**Локализация базы.** Политика обещает хранение данных граждан РФ на
территории России (ч. 5 ст. 18 152-ФЗ). Neon во Франкфурте этому не
соответствует. Для теста и закрытого круга пользователей приемлемо, для
публичного запуска — нет.

**Уведомление Роскомнадзора** об обработке персональных данных и отдельно о
трансграничной передаче — подаются до начала обработки.
